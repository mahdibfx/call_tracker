Call Tracker — Outstanding Backend Work

Updated after integrating against the real /call-tracker/* API. Only one item is still open.

Resolved on the API side already. The app had been calling a stale /api/* path. Once it moved to /call-tracker/*, two of the three original asks turned out to already exist — and the duplicate-student problem disappeared with them (2227 clean records vs 2682 with 412 duplicated ids).

1. Last-called date on students Already live

No backend work needed. GET /call-tracker/students returns last_call per student; the app reads last_call.date and renders "Called at 02/01/2027" under the name. 315 of 2227 students currently have one.

2. Group type + responsible teacher Already live

No backend work needed. GET /call-tracker/groups already carries type, category and teacher_name. The app shows "Language Level • Onsite" and the teacher under each group name.

One thing worth knowing: category and type are free-text columns and come through English-only, while group names are often Arabic. The app renders them verbatim — no mapping, no translation. If they should be localised, that needs deciding (backend-supplied labels, or a mapping in the app).

3. Call history endpoint Still needed

This one genuinely doesn't exist — every candidate path returns 404:

GET /call-tracker/calls              -> 404
GET /call-tracker/calls?studentId=28 -> 404
GET /call-tracker/students/28/calls  -> 404

Calls written via POST /call-tracker/calls can't be read back. Only last_call (the single most recent, embedded per student) is available.

Proposed: GET /call-tracker/calls

Query paramRequired?Notes
studentIdoptionalOne student's history — for the student detail screen.
agentIdoptionalOne agent's calls — for supervisor review.
page / limitoptionalSame pagination shape as /call-tracker/students.

Response: the same records already stored on write, in the existing { data, pagination } envelope.

Not blocking the app. The History tab now reads an on-device store, so agents can see their own past calls offline without this endpoint. What's still missing is the supervisor view — cross-agent history, and any history at all on a fresh install or a replaced handset. Local storage is per-device and lost on uninstall.

Also worth fixing

  • agentName is always "" in the POST /call-tracker/calls response — the login JWT doesn't carry the name. Harmless for the app (it uses the name from login), but it means stored call rows can't be attributed by name server-side.
  • The stale /api/students endpoint still serves duplicates (412 duplicated ids). Nothing points at it any more, but it's worth removing so nothing picks it up again.
