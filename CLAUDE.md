# call_tracker

- Flutter is not on `PATH`. Use the fvm copy: `export PATH="/Users/mahdi/fvm/versions/3.38.1/bin:$PATH"` before `flutter analyze` / `flutter test` / `flutter build apk --debug`.
- No emulator is configured — the only mobile device is a wirelessly-connected physical iPhone, and the app is Android-first (`phone_state`, native dialer intent), so UI behaviour cannot be verified locally. Analyze + tests + a debug APK build is as far as automated verification goes.
- The four tabs live in an `IndexedStack` in `root_view.dart`, so a tab's `initState` runs once per session and never again. Anything that needs to re-fetch must listen to `RefreshSignal` (`lib/data/refresh_signal.dart`); it is fired on tab change, on app resume, and after a call is submitted.
- `ApiService` getters return `null` when a request fails (vs an empty list when the server genuinely has nothing). Screens must keep their existing data on `null` rather than blanking the list.
- Nothing derived from `CallVerification` / `CallRecord.verdictKind` / `finalResult` may be rendered in agent-facing UI (`call_view`, `call_summary_view`, `history_view`) — not the verdict, not the note, not "we checked your call log". It is computed and sent to the backend, and the agent is never shown that the check happened. There is no exception any more: the Dashboard's test-mode monitor has been removed, so no screen in the app renders a verdict.
- The History tab reads `CallHistoryStore` (on-device, `shared_preferences`) — the backend has no call-history endpoint. It is scoped to the logged-in agent, and shows only what the agent themselves reported (student, reason, outcome, duration, notes).
- The per-student Call Log (`student_calls_view.dart`, `GET /ManagementStudent/student-calls/:id`) is a root-level envelope route, not a `/call-tracker` one. The backend refuses call-tracker agent tokens there with 403 — same guard that now breaks `GET /groups/:id/students` — so it renders its error state until that is fixed backend-side.
