# call_tracker

- Flutter is not on `PATH`. Use the fvm copy: `export PATH="/Users/mahdi/fvm/versions/3.38.1/bin:$PATH"` before `flutter analyze` / `flutter test` / `flutter build apk --debug`.
- No emulator is configured — the only mobile device is a wirelessly-connected physical iPhone, and the app is Android-first (`phone_state`, native dialer intent), so UI behaviour cannot be verified locally. Analyze + tests + a debug APK build is as far as automated verification goes.
- The four tabs live in an `IndexedStack` in `root_view.dart`, so a tab's `initState` runs once per session and never again. Anything that needs to re-fetch must listen to `RefreshSignal` (`lib/data/refresh_signal.dart`); it is fired on tab change, on app resume, and after a call is submitted.
- `ApiService` getters return `null` when a request fails (vs an empty list when the server genuinely has nothing). Screens must keep their existing data on `null` rather than blanking the list.
- Nothing derived from `CallVerification` / `CallRecord.verdictKind` / `finalResult` may be rendered in agent-facing UI (`call_view`, `call_summary_view`) — not the verdict, not the note, not "we checked your call log". It is computed and sent to the backend, and the agent is never shown that the check happened. The one exception is the Dashboard's `kShowCallMonitor` block, which is a test-mode screen behind a flag.
- Incoming calls are detected natively, not from Dart: a manifest-declared `IncomingCallReceiver` for `PHONE_STATE` (one of the few implicit broadcasts still exempt from the Android 8+ ban), with the state machine and queue in `IncomingCallStore.kt`. It has to run with no Activity and no Flutter engine, so its state lives in its own `call_tracker_incoming` SharedPreferences file and reaches Dart over the existing `call_tracker/native_call` MethodChannel — deliberately not via `shared_preferences`, which would mean writing that plugin's `flutter.`-prefixed keys from Kotlin. `phone_state` only sees calls while the isolate is alive and cannot be the engine for this.
- RINGING is what distinguishes an incoming call from an outgoing one: outgoing goes OFFHOOK → IDLE with no RINGING. Anything keying off "a call happened" must check that, or it will double-log every call the agent places.
- Adding a value to `CallReason` needs an entry in `_reasonIcons` in `student_detail_view.dart` — it does `_reasonIcons[reason]!` and will crash on a missing one. The outbound picker iterates `CallReason.outgoing`, not `.values`, so incoming-only reasons stay out of it.
- Two test flags, both of which must be `false` before the app ships to agents: `kShowCallMonitor` (`dashboard_view.dart`) and `kIncomingCallTestMode` (`lib/data/test_mode.dart`). The second makes an incoming caller who matches nothing resolve to `IncomingCallService.mockCaller` instead of being dropped, because `GET /students/lookup` isn't deployed — with it on, the app asks the agent to log every call he receives, private ones included.
- `flutter_test` installs an `HttpOverrides` that answers every request with a 400, so code that calls `ApiService` from a test resolves to `null` fast without touching the network — no mocking needed to exercise a path that falls through a failed lookup.
- `permission_handler` has no call-log permission. `Permission.phone` covers `READ_CALL_LOG` on Android as long as it is declared in the manifest — that is why the existing single `Permission.phone.request()` is enough.
- Every launcher/status-bar/web icon in the repo is generated by `tool/generate_app_icons.py` (`python3 tool/generate_app_icons.py`, needs Pillow and the Material Icons OTF in the fvm Flutter cache). Change the mark there and re-run; hand-editing the PNGs means the next run silently reverts you. It writes `assets/icon/`, the Android legacy mipmaps + adaptive foreground, `drawable-*/ic_notification.png`, the whole iOS appiconset, and `web/icons` + `web/favicon.png`.
- A screen *can* be eyeballed without a device: write a throwaway test with `matchesGoldenFile`, run `flutter test <file> --update-goldens`, and look at the PNG it writes. Text comes out as filled boxes (widget tests ship no real font), so it verifies layout, images and colour — not copy.
- `applicationId` is still `com.example.call_tracker`, which the Play Store rejects. It is not a rename you can do alone: it is duplicated in `android/app/google-services.json` and `lib/firebase_options.dart`, so it needs a new Android app registered in the `calltracker-b3aca` Firebase project and a fresh `google-services.json`.
